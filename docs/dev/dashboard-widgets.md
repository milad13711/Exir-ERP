# افزودن ویجت به داشبورد

داشبورد از یک **رجیستری ویجت** ساخته می‌شود. مدیر (OWNER/ADMIN) چیدمان شرکت را تنظیم می‌کند (فعال/غیرفعال، ترتیب، اندازه، حالت نمایش)،
و هر کاربر می‌تواند در همان چارچوب ویجت‌ها را برای خودش پنهان یا جابه‌جا کند. کاربر هرگز ویجتی را نمی‌بیند که ماژولش نصب نیست یا مجوزش را ندارد.

## ۱) ثبت در سرور — `apps/backend-core/src/dashboard/dashboard-widgets.ts`

یک ورودی به `WIDGET_REGISTRY` اضافه کنید:

```ts
w({
  key: 'my-widget',              // یکتا؛ همان کلید در رندرر کلاینت
  title: 'عنوان فارسی',
  description: 'توضیح کوتاه برای پنل ویرایش',
  moduleCode: 'my-module',       // ماژولی که باید نصب باشد؛ null = هسته
  perm: { modules: ['my-module'], level: 'any' }, // null = بدون ماتریس دسترسی
  sizes: ['M', 'L', 'FULL'],     // S (نصف عرض در موبایل/یک‌چهارم دسکتاپ) | M (نصف) | L (دوسوم) | FULL
  variants: ['list', 'compact'], // حالت‌های نمایش؛ رندرر خودش معنایشان را تعیین می‌کند
  defaultSize: 'M',
  defaultVariant: 'list',
  order: 120,                    // ترتیب پیش‌فرض (یکتا؛ تست یکتایی را چک می‌کند)
  defaultEnabled: true,          // false = برای شرکت‌های موجود خودکار روشن نمی‌شود
})
```

`perm.level`:
- `any`: «مشاهده‌ی همه» یا «فقط خودم» کافی است (endpoint خودش داده را به دامنه‌ی کاربر محدود می‌کند).
- `all`: فقط «مشاهده‌ی همه» (ویجت‌هایی که جمع کل شرکت‌اند، مثل KPIهای `/dashboard/summary`).
- `modules` چندتایی = کافی است یکی از آن‌ها مجوز بدهد.

## ۲) رندرر کلاینت — `apps/web-panel/src/components/dashboard/DashboardWidgets.tsx`

کامپوننتی با props `{ size, variant }` بنویسید و در `WIDGET_RENDERERS` با همان `key` ثبت کنید. اگر داده‌اش از `GET /dashboard/summary` می‌آید،
`useContext(SummaryContext)` را بخوانید و کلید را به `SUMMARY_WIDGET_KEYS` اضافه کنید (فقط وقتی حداقل یکی از این ویجت‌ها در چیدمان باشد درخواست زده می‌شود).
در غیر این صورت ویجت داده‌ی خودش را با endpoint ماژول خودش بگیرد. قواعد:

- حالت‌های loading / empty / error داشته باشد و ارتفاعش هنگام بارگذاری جهش نکند (از `LOADING`/`empty` یا اسکلت استفاده کنید).
- حاشیه‌ی بیرونی (`mb-*`) نگذارید؛ فاصله را grid داشبورد می‌دهد. `min-w-0` و `break-words` را رعایت کنید (موبایل ۳۲۰px).
- هدف‌های لمسی ≥ ۴۰px.

## ۳) امنیت

مخفی‌شدن ویجت فقط UX است. **endpoint داده باید خودش مجوز و دامنه (`viewScope`) را اعمال کند.** `GET /dashboard/summary` برای غیرمدیر فقط با
«مشاهده‌ی همه»ی ماژول مربوط عدد واقعی می‌دهد؛ اگر بخش جدیدی به خلاصه اضافه می‌کنید همان الگوی `can(...)` را در کنترلر ادامه دهید و `perm` ویجت را هم‌سطح آن بگذارید.

## ۴) تست

`dashboard-widgets.spec.ts` یکتایی کلید/ترتیب و معتبر بودن پیش‌فرض‌ها را برای کل رجیستری بررسی می‌کند؛ برای ویجت جدید در صورت منطق دسترسی خاص یک case اضافه کنید.

## ذخیره‌سازی

جدول `dashboard_layouts` (`scope` = `COMPANY` یا `USER`، `ownerKey` = `''` یا شناسه‌ی کاربر). ورودی PUT سخت‌گیرانه اعتبارسنجی می‌شود؛ هنگام خواندن،
ورودی‌های منسوخ (ویجت حذف‌شده، اندازه‌ی نامعتبر) بی‌صدا ترمیم/حذف می‌شوند. ویجت‌های جدید که در چیدمان ذخیره‌شده نیستند، با تنظیمات پیش‌فرض به انتها اضافه می‌شوند.

## API

- `GET /dashboard/layout` — چیدمان مؤثر کاربر (فقط ویجت‌های مجاز) + فهرست شخصی‌سازی
- `PUT|DELETE /dashboard/layout/me` — ذخیره / بازنشانی شخصی (پنهان + ترتیب)
- `GET|PUT|DELETE /dashboard/layout/company` — فقط مدیر
