# استقرار اختصاصی (On-Premise) اکسیر ERP

این راهنما برای تننت‌های حساس به امنیت است که می‌خواهند کل سیستم — هسته،
دیتابیس و پنل وب — را روی سرور اختصاصی خودشان اجرا کنند، بدون هیچ
وابستگی دائمی به زیرساخت ابری اکسیر.

## معماری این بسته

یک `docker-compose.on-premise.yml` در ریشه‌ی مخزن، چهار سرویس را بالا
می‌آورد:

| سرویس | نقش |
|---|---|
| `postgres` | دیتابیس PostgreSQL محلی — هم Control Plane (فهرست تننت، ماژول‌ها) و هم دیتابیس تننت روی همین یک نمونه |
| `backend` | هسته‌ی NestJS — دقیقاً همان کدی که نسخه‌ی ابری هم از آن استفاده می‌کند، با `DEPLOYMENT_MODE=ON_PREMISE` |
| `web` | پنل Next.js |
| `proxy` | Nginx — تنها پورت باز روی سرور؛ `/api/*` را به backend و بقیه را به web هدایت می‌کند |

این استقرار **تک‌تننتی** است: کل بسته فقط برای همان یک سازمانی که لایسنس
گرفته کار می‌کند، نه چند تننت مثل نسخه‌ی ابری.

## پیش‌نیازها

- یک سرور لینوکسی (یا هر سیستمی) با Docker و Docker Compose نصب‌شده.
- حداقل ۲ هسته‌ی CPU و ۴ گیگابایت RAM برای شروع.
- یک **کد لایسنس** و **کلید عمومی لایسنس** که تیم اکسیر پس از خرید برایتان
  صادر و ارسال می‌کند (بخش «چرخه‌ی عمر لایسنس» را ببینید).

## مراحل نصب

```bash
git clone <آدرس مخزن> exir-erp && cd exir-erp
cp .env.on-premise.example .env
```

سپس فایل `.env` را باز کنید و همه‌ی مقادیر را پر کنید:

- `POSTGRES_PASSWORD` — یک رمز قوی و تصادفی برای دیتابیس محلی.
- `JWT_SECRET` — با `openssl rand -hex 32` تولید کنید.
- `LICENSE_KEY` و `LICENSE_PUBLIC_KEY_PEM` — دقیقاً همان مقادیری که تیم
  اکسیر هنگام صدور لایسنس برایتان ارسال کرده (کپی کامل، شامل `\n`ها).
- `ON_PREM_ORG_NAME`، `ON_PREM_OWNER_NAME`، `ON_PREM_OWNER_PHONE` — نام
  سازمان و اولین کاربری که با نقش «مدیر سیستم» می‌تواند وارد شود.

سپس:

```bash
docker compose -f docker-compose.on-premise.yml up -d --build
```

اولین بالا آمدن چند دقیقه طول می‌کشد: ساخت ایمیج‌ها، اجرای مایگریشن‌های
دیتابیس، و **راه‌اندازی خودکار تننت شما بر اساس ماژول‌های مجاز در
لایسنس** (بدون هیچ تماس دستی با API). لاگ‌ها را می‌توانید این‌طور ببینید:

```bash
docker compose -f docker-compose.on-premise.yml logs -f backend
```

وقتی خط `[entrypoint] starting server...` را دیدید، سامانه روی
`http://<آی‌پی-یا-دامنه-سرور>:<EXPOSED_PORT>` در دسترس است. ورود با شماره
موبایلی که در `ON_PREM_OWNER_PHONE` گذاشتید انجام می‌شود.

## چرخه‌ی عمر لایسنس

لایسنس یک توکن امضاشده با Ed25519 است — کاملاً **آفلاین قابل تأیید**: سرور
شما هیچ‌وقت لازم نیست به اینترنت وصل باشد تا لایسنسش را تأیید کند. هر
لایسنس شامل نام سازمان، فهرست ماژول‌های مجاز، تعداد کاربر مجاز، و تاریخ
انقضا است.

- **قبل از انقضا**: همه‌چیز عادی کار می‌کند.
- **پس از انقضا (تا ۷ روز)**: سامانه در «مهلت اضافه» قرار می‌گیرد — همچنان
  کار می‌کند، اما در سربرگ به همه‌ی کاربران هشدار داده می‌شود.
- **پس از پایان مهلت اضافه**: تمام دسترسی به سامانه (به‌جز صفحه‌ی وضعیت
  لایسنس) مسدود می‌شود تا لایسنس تمدید شود.

اگر `CONTROL_PLANE_CHECKIN_URL` را در `.env` تنظیم کنید، سامانه هر ۶ ساعت
یک‌بار (به‌صورت best-effort و فقط اگر اینترنت داشته باشد) با اکسیر چک‌این
می‌کند تا ابطال زودهنگام لایسنس (مثلاً به دلیل عدم پرداخت) را هم تشخیص
دهد. اگر اینترنت نداشته باشد یا این متغیر خالی بماند، سامانه فقط بر اساس
همان تأیید آفلاین امضا و تاریخ انقضا عمل می‌کند — هیچ‌وقت به‌خاطر نبود
اینترنت قفل نمی‌شود.

### تمدید یا ارتقای لایسنس

۱. با پشتیبانی اکسیر تماس بگیرید و لایسنس جدید بگیرید.
۲. مقدار `LICENSE_KEY` را در `.env` با کد جدید جایگزین کنید.
۳. سرویس backend را ری‌استارت کنید:
   ```bash
   docker compose -f docker-compose.on-premise.yml up -d backend
   ```

## پشتیبان‌گیری

تمام داده در volume نام‌گذاری‌شده‌ی `exir_postgres_data` نگه‌داری می‌شود.
برای پشتیبان‌گیری دستی:

```bash
docker compose -f docker-compose.on-premise.yml exec postgres \
  pg_dumpall -U postgres > backup-$(date +%F).sql
```

## محدودیت‌های شناخته‌شده (مهم)

- **ارسال پیامک واقعی به اکسیر پیامک (نماینده‌ی لیمو پیامک، `api.limosms.com`)
  وصل و ساختار درخواستش روی همان API واقعی تأیید شده — فقط با تنظیم دو
  متغیر فعال می‌شود.** `EXIR_SMS_API_KEY` و `EXIR_SMS_SENDER_LINE` را در
  `.env` پر کنید و backend را ری‌استارت کنید. شکل دقیق بدنه‌ی درخواست
  (نام فیلدها، آرایه‌بودن `MobileNumber`) با ارسال واقعی به سرور لیمو و
  خواندن پیام‌های خطای اعتبارسنجی‌اش پیدا و تأیید شد (نه فقط از روی
  مستندات) — تنها چیزی که تست نشده، صحت خودِ ApiKey واقعی است. تا وقتی
  این دو متغیر خالی باشند (یا ارسال واقعی با خطا مواجه شود)، کد ورود
  همچنان در پاسخ API هم برگردانده می‌شود (`OTP_DEV_ECHO=true`) تا ورود
  اصلاً ممکن باشد — **پیش از قرار دادن این استقرار در معرض شبکه‌ی
  نامطمئن، حتماً این دو متغیر را پر کنید**، وگرنه هرکسی که به شبکه
  دسترسی داشته باشد می‌تواند کد ورود هر کاربری را از پاسخ API بخواند.
  توجه: `api.exirsms.ir` هنوز در DNS ثبت نشده (فقط سایت معرفی محصول روی
  `exirsms.ir` اجرا می‌شود)، برای همین مستقیم به `api.limosms.com` وصل
  می‌شویم؛ در صورت نیاز با `EXIR_SMS_API_BASE_URL` قابل تغییر است.
- **رجیستری npm (`registry.npmjs.org`) در برخی شبکه‌های داخل ایران کامل
  مسدود است** — نشانه‌اش این است که `docker compose build` روی یک مرحله‌ی
  `npm ci` بی‌هیچ خطایی برای مدت طولانی گیر می‌کند. `NPM_REGISTRY` را در
  `.env` به یک آینه‌ی در دسترس تنظیم کنید (در تست همین راهنما،
  `https://mirror-npm.runflare.com` کار کرد؛ آینه‌های دیگر را هم می‌توان
  امتحان کرد).
- اگر پورت ۸۰ روی سرور از قبل توسط سرویس دیگری اشغال شده (رایج در سرورهای
  اشتراکی)، مقدار `EXPOSED_PORT` را در `.env` به پورت دیگری (مثلاً ۸۰۸۰)
  تغییر دهید.
- **این راهنما یک‌بار به‌طور کامل روی یک سرور واقعی (اوبونتو ۲۴.۰۴، بدون
  Docker از قبل) اجرا و تأیید شده است**: نصب Docker، build هر دو ایمیج با
  آینه‌ی npm، بالا آمدن هر چهار سرویس، migrate/seed/bootstrap خودکار، و
  ورود واقعی با OTP از طریق آدرس عمومی سرور — همه با موفقیت انجام شد.
