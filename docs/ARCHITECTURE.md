# Exir ERP — معماری کلی (پیش‌نویس مرحله ۱)

مرجع معماری بنیادی پروژه Exir ERP — سیستم ERP ابری فارسی/راست‌چین با معماری ماژولار، مشابه Odoo از نظر دامنه‌ی امکانات ولی با UI/UX ساده‌تر و مدرن‌تر.

## تصمیمات استک (تأیید‌شده با کاربر)

| لایه | انتخاب | دلیل |
|---|---|---|
| بک‌اند / هسته API | NestJS (Node.js + TypeScript) | معماری ماژولار native (Nest Modules ≈ ماژول‌های ERP)، DI، یک زبان با فرانت |
| دیتابیس | PostgreSQL | schema/database per-tenant، پشتیبانی قوی از JSONB برای فیلدهای سفارشی ماژول‌ها |
| فرانت‌اند وب | Next.js + Tailwind CSS | RTL نیتیو، PWA، رندر سمت سرور برای سرعت روی اینترنت محدود |
| موبایل | PWA (installable) + سنکرون آفلاین (IndexedDB) | یک کدبیس برای وب و موبایل، OTP login |
| ویندوز | بسته‌بندی همان وب‌اپ با Tauri/Electron + کش محلی | جلوگیری از دوباره‌نویسی UI |
| صف/کش | Redis | صف کارهای پس‌زمینه (billing، sync، وظایف) و session |

## مدل چند-تننتی

- هر تننت یک **دیتابیس مجزا** روی کلاستر PostgreSQL مرکزی (provisioning خودکار هنگام خرید پکیج).
- یک دیتابیس مرکزی «Control Plane» شامل: فهرست تننت‌ها، اشتراک‌ها، فاکتورها، فروشگاه ماژول، تیکت‌های پشتیبانی.
- **نسخه on-premise**: برای تننت‌های حساس به امنیت، امکان صدور لایسنس + پکیج Docker جهت اجرای کامل سیستم (هسته + ماژول‌های خریداری‌شده) روی سرور اختصاصی خودشان، با همان مکانیزم لایسنس/فعال‌سازی که Control Plane مرکزی صادر می‌کند.

## معماری ماژولار

- هر ماژول (مثل CRM، انبار، حسابداری، منابع انسانی) یک پکیج مستقل در `modules/` با:
  - `backend/` (NestJS module قابل نصب/حذف پویا)
  - `frontend/` (کامپوننت‌های صفحه، بر پایه‌ی `packages/ui-kit` مشترک)
  - `manifest.json` (نام، نسخه، وابستگی به ماژول‌های دیگر، مجوزهای لازم)
- فروشگاه ماژول (Module Store) در پنل هر تننت، لیست ماژول‌های نصب‌شده/قابل‌خرید را نشان می‌دهد.
- تنظیمات هر ماژول از یک اسکیمای استاندارد پیروی می‌کند و در بخش «تنظیمات مرکزی ERP» رندر یکپارچه می‌شود.

## استانداردهای UI/UX (الزامی برای همه‌ی ماژول‌ها)

- فارسی و راست‌چین کامل، فونت وزیر (Vazirmatn).
- تقویم شمسی در همه‌جا (انتخاب‌گر تاریخ، فیلترها، گزارش‌ها).
- اعداد فارسی + جداکننده‌ی هزارگان در همه‌ی نمایش اعداد.
- کامپوننت‌های مشترک از `packages/ui-kit` (دکمه، جدول، فرم، مودال، تقویم، کارت KPI) — هیچ ماژولی کامپوننت سفارشی موازی نمی‌سازد.
- کاملاً موبایل‌ریسپانسیو (mobile-first breakpoints).
- هدر ثابت سراسری: وضعیت اشتراک + روزهای باقی‌مانده + دکمه‌ی تمدید/ارتقا + دکمه‌ی پشتیبانی زنده (چت).

## زیرساخت‌های پایه (پیش‌فرض روی هسته، نه ماژول جدا)

- مدیریت کاربران، نقش‌ها و سطوح دسترسی (RBAC).
- یادآوری و وظیفه (Task/Reminder) — شامل تبدیل تیکت پشتیبانی به وظیفه و ارجاع به کارشناس.
- لاگ فعالیت‌ها (Audit Log) و لاگ خطاهای سیستم.
- مستندات API / Webhooks / MCP برای اتصال نرم‌افزار و ایجنت‌های مستقل هر تننت.

## دسترسی داخل ایران

- تمام asset های حیاتی هسته (فونت، آیکون، کتابخانه‌های JS/CSS اصلی) self-hosted روی سرور داخلی، بدون وابستگی به CDN بین‌المللی.
- در نسخه‌ی دسکتاپ/موبایل، صف محلی برای درخواست‌هایی که هنگام قطعی اینترنت ثبت می‌شوند و به‌محض اتصال sync می‌شوند.

## وضعیت این مرحله

مرحله‌ی فعلی فقط **طراحی UI/UX** است (مستقل از بک‌اند). خروجی در پوشه‌ی `design/` قرار می‌گیرد. پیاده‌سازی بک‌اند/فرانت واقعی در فازهای بعدی، پس از تأیید طراحی، آغاز می‌شود.
