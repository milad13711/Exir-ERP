# افزودن ماژول جدید — چک‌لیست

این سند، الگوی واقعی پیاده‌سازی‌شده در کدبیس را توضیح می‌دهد (نه طرح اولیه‌ی `ARCHITECTURE.md` که ماژول‌ها را پکیج‌های مستقل با `manifest.json` فرض کرده بود). در عمل: هر «ماژول» چند کنترلر/سرویس NestJS داخل همان اپ یک‌پارچه‌ی `backend-core` است که با یک ردیف در جدول `module_definitions` (کاتالوگ) و گارد `ModuleGuard` به‌صورت واقعی فعال/غیرفعال می‌شود.

## ۱. تصمیم‌های اول

- **کد ماژول** (`code`): انگلیسی، kebab-case، کوتاه — مثلاً `supplier-risk`.
- **هسته یا پولی؟** فقط `tasks` هسته و رایگان است. هر چیز دیگر پیش‌فرض پولی و `isCore: false`.
- **وابستگی (`dependsOn`)**: اگر ماژول جدید روی داده/منطق ماژول دیگری سوار می‌شود (مثلاً چک روی فروش، فروش روی حسابداری و CRM)، آن را در `dependsOn` بگذار — گارد به‌صورت انتقالی (transitive) کل زنجیره را چک می‌کند.
- **گِیت روی کل ماژول یا فقط چند endpoint؟** اگر ویژگی جدید بخشی از یک ماژول بزرگ‌تر است (مثلاً امضای تحویل داخل فروش)، گیت را روی سطح متد بگذار (`@RequireModule` روی همان متدها، نه کلاس) تا override کند؛ گارد به‌خاطر `dependsOn` همچنان ماژول والد را هم چک می‌کند.
- **قیمت**: بین ماژول‌های کامل (۱۹۰–۴۹۰ هزار تومان/ماه) و افزونه‌های کوچک (۹۰ هزار تومان/ماه) قیاس کن.

## ۲. بک‌اند

1. در `prisma/control/seed.ts`، آرایه‌ی `modules` را ویرایش کن: `code`, `name`, `description`, `category`, `priceMonthly`, `isCore`, `version: '1.0.0'`, `dependsOn`.
2. اگر ماژول **جدیداً** روی چیزی که قبلاً بدون گیت کار می‌کرد بسته می‌شود، تننت‌های موجود را در `grandfatheredCodes` (همان فایل) اضافه کن — وگرنه یک تننت فعال، یک‌شبه دسترسی‌اش را از دست می‌دهد.
3. روی کنترلر(های) مربوطه:
   ```ts
   @UseGuards(JwtAuthGuard, ModuleGuard)
   @RequireModule('your-module-code')
   ```
   کلاس یا فقط متدهای مشخص — طبق تصمیم بالا.
4. اگر کنترلر تازه import شده به یک ماژول Nest جدید نیاز دارد، `ModuleGuardModule` را در `imports` آن اضافه کن (برای رزولوشن `ModuleGuard`).
5. تست محلی: یک ردیف `TenantModule` را دستی حذف/به `DISABLED` تغییر بده و مطمئن شو endpoint واقعاً ۴۰۳ می‌دهد؛ دوباره فعال کن و ۲۰۰ بگیر. صرفاً code review کافی نیست — این گارد قبلاً یک‌بار باگ داشت (`isCore` همیشه اجازه می‌داد) و فقط با تست زنده کشف شد.

## ۳. فرانت‌اند (پنل تننت)

- `WorkspaceProvider` (`src/lib/workspace-context.tsx`) یک‌بار `/modules` را می‌گیرد و `installedModules: Set<string>` را در اختیار همه می‌گذارد.
- در کامپوننت مربوطه: `const enabled = useWorkspace().installedModules.has('your-module-code')` و بر اساس آن، هم فراخوانی API را شرطی کن، هم رندر UI را.
- خود `/modules` (فروشگاه) و صفحه‌ی کاتالوگ ادمین معمولاً نیازی به تغییر ندارند — کاتالوگ عمومی است.

## ۴. پنل ادمین

- کاتالوگ (`/catalog`) نسخه و پیش‌نیازها را از همان جدول می‌خواند — نیازی به تغییر دستی نیست مگر بخواهی چیزی را از UI ویرایش کنی.
- برای فعال/غیرفعال‌سازی دستی یک ماژول برای یک تننت خاص، رابط موجود در `/tenants/:id` استفاده می‌شود.

## ۵. دیپلوی

- `./scripts/deploy.sh backend` (فقط بک‌اند اگر فرانت تغییری نکرده) — کاتالوگ و grandfather به‌صورت خودکار توسط `docker-entrypoint.sh` روی هر ری‌استارت seed می‌شوند، نیازی به migrate دستی برای این بخش نیست (کاتالوگ در control-plane است، نه tenant-plane).
- اگر مدل Prisma عوض شده (ستون/جدول جدید در `prisma/tenant/schema.prisma`)، مایگریشن آن **دیگر نیازی به دستور دستی ندارد** — از این پس روی هر ری‌استارت بک‌اند به همه‌ی تننت‌ها اعمال می‌شود (`migrate-all-tenants.ts`، بخش «زیرساخت دیپلوی» را ببین).

## نمونه‌ی واقعی

`supplier-risk` و `delivery-signature` (۲۰۲۶/۰۶/۱۱) دقیقاً همین الگو را دنبال کردند: افزونه‌ی کوچک روی ماژول بزرگ‌تر، گیت سطح متد، grandfather برای تننت موجود، و `installedModules` سمت فرانت. برای جزئیات کامل کد، `apps/backend-core/src/crm/supplier-risk.service.ts` و `apps/backend-core/src/sales/invoices.controller.ts` (متدهای `sendDeliveryCode`/`confirmDelivery`) را ببین.

## ۶. اسنادی که تأیید مدیر می‌خواهند (کارتابل تأیید)

هر ماژولی که سندی دارد که باید مدیر (نه کارشناس) تأیید کند، باید به کارتابل مشترک (`ApprovalsService`، ماژول سراسری) وصل شود — اعلان مدیران، نمایش در کارتابل و داشبورد، و دکمه‌های «تأیید» / «تأیید و اجازه‌ی درج مهر و امضا» / «رد» خودکار فراهم می‌شوند:

1. در سرویس ماژول `ApprovalsService` را inject کن و `OnModuleInit` را پیاده کن:
   ```ts
   onModuleInit() {
     this.approvals.registerHandler('MY_DOC', {
       approve: async (ctx, id, opts) => { /* opts.stampApplied: مهر/امضا مجاز است */ },
       reject: async (ctx, id, opts) => { /* opts.note: دلیل رد */ },
     });
   }
   ```
2. هنگام ایجاد سند: `await this.approvals.request(ctx, { moduleCode, entityType: 'MY_DOC', entityId, title, summary, link, isOfficial /* سند رسمی؟ دکمه‌ی مهر و امضا */, assigneeUserId /* اختیاری؛ خالی = مدیران */ })`.
3. اگر سند از مسیر خود ماژول هم قابل تأیید است، بعد از تصمیم `approvals.closeForEntity(ctx, 'MY_DOC', id, 'APPROVED' | 'REJECTED')` را صدا بزن تا کارتابل هم بسته شود؛ در handler این را تکرار نکن (پرچم `fromApprovals`).
4. خود اکشن تأیید باید سمت سرور فقط برای OWNER/ADMIN (یا تأییدکننده‌ی ارجاع‌شده) مجاز باشد.

نگهبان‌ها: `request()` بدون handler ثبت‌شده خطا می‌دهد و تست `approvals-wiring.spec.ts` همه‌ی `entityType`های ارسالی را با `registerHandler` مطابقت می‌دهد. اتصال‌های فعلی: JOB_APPLICANT، PURCHASE_ORDER، SALES_INVOICE (رسمی)، CONTRACT، LEAVE_REQUEST، PROJECT_STAGE. برچسب فارسی ماژول در `ApprovalsList.tsx` (`MODULE_LABELS`) اضافه شود.

## ۷. مشاهده / ویرایش / حذف رکوردها (استاندارد کنترل)

هر رکورد باید در UI با کلیک باز شود (جزئیات کامل) و طبق نوعش این قواعد را داشته باشد:

- **داده‌ی پایه و عملیاتی** (مخاطب، پرسنل، آگهی، نوبت، وظیفه و ...): ویرایش و حذف مستقیم؛ حذف با `safeDelete` (`common/safe-delete.ts`) اگر رکورد به سوابق دیگر وصل باشد پیام روشن می‌دهد. دکمه‌ی حذف: `components/ui/DeleteRecordButton`.
- **اسناد مالی** (فاکتور، سند حسابداری، سفارش خرید): پیش‌نویس آزادانه ویرایش/حذف می‌شود؛ سند قطعی‌شده هرگز حذف/ویرایش نمی‌شود و فقط **ابطال** دارد (سند معکوس + برگشت موجودی). ابطال توسط غیرمدیر با `ApprovalsService.runOrRequest` به کارتابل مدیر می‌رود. ابطال فاکتور فقط بدون پرداخت و مرجوعی؛ در غیر این صورت مرجوعی/برگشت پرداخت.
- **ردیابی**: `AuditInterceptor` همه‌ی ایجاد/ویرایش/حذف/تأیید/ابطال را به‌صورت `ماژول.موجودیت.عمل` در لاگ فعالیت (تنظیمات ← لاگ‌ها) ثبت می‌کند.
- ماژول جدید: endpoint حذف/ویرایش را با `permissions.assertDelete/assertEdit` بسازد و در مودال جزئیات دکمه‌ها را بگذارد.
